## Project Overview

IseoGraph visualizes protein primary structures as interactive directed acyclic graphs. It integrates isoforms and single amino acid variations from UniProt with peptide mass spectrometry data. The graph structure is generated by a modified ProtGraph (https://github.com/Tisch-hinten-rechts/ProtGraph, `dev` branch).

## Commands

### Backend (from project root)
```bash
poetry install                    # Install Python dependencies
python manage.py runserver        # Start Django dev server (port 8000)
pytest                            # Run all backend tests
coverage run -m pytest && coverage report  # Test coverage
```

### Frontend (from `frontend/`)
```bash
pnpm install                      # Install dependencies
pnpm dev                          # Vite dev server (port 5173, proxies /api to :8000)
pnpm build                        # TypeScript check + production build
pnpm lint                         # ESLint
pnpm format                       # Prettier
pnpm typecheck                    # tsc --noEmit
pnpm test                         # Vitest (jsdom)
pnpm storybook                    # Storybook dev (port 6006)
```

### Full stack dev
Run `python manage.py runserver` and `cd frontend && pnpm dev` in separate terminals.

## Architecture

### Data Flow
```
UniProt ID → Backend fetches .txt → ProtGraph CLI generates .graphml
  → convert_graphml_to_json.py (NetworkX) → nodes.json + edges.json
  → Frontend Zustand store loads → layout algorithm → React Flow renders
```

### Backend (`backend/`)
Thin Django REST API with four endpoints defined in `backend/urls.py`:
- `POST /api/generate_base_graph/` — main pipeline: fetch UniProt data → run ProtGraph → convert to JSON
- `POST /api/convert_file/` — convert existing .graphml to JSON
- `GET /api/get_available_files/` — list .graphml files in `data/`
- `POST /api/upload_file/` — upload peptide CSV files

`backend/views.py` contains all endpoint logic. `backend/consts.py` defines project paths and a `TEST_MODE` flag that switches between `data/` and `test_data/` directories.

`scripts/convert_graphml_to_json.py` is the critical conversion layer — parses GraphML with NetworkX and outputs React Flow-compatible node/edge JSON to `generated/`.

### Frontend (`frontend/src/`)
- **`graph/store.ts`** — Zustand store: single source of truth for nodes, edges, layout mode, isoform colors, peptide intensity state, UI toggles
- **`graph/graph-manager.tsx`** — main React Flow wrapper; supports dual-screen split view for comparing intensity sources
- **`graph/layout/`** — custom layout algorithms: linear (left-to-right) and snake (boustrophedon wrapping). BFS-based position indexing with symmetrical Y-offset for variant nodes
- **`graph/generation-utils/`** — transforms raw JSON into typed nodes/edges with parsed PeptideLogs, intensity stats, and normalized extremes
- **`components/sequence-node/`** — amino acid node component with intensity glow
- **`components/arrow-edge/`** — bezier edge with isoform coloring and intensity-based width
- **`components/side-menu/`** — protein selection, settings, user guide panels
- **`components/on-screen-menu/`** — layout controls, intensity source selection, color scale picker
- **`theme/types.tsx`** — all TypeScript interfaces (PeptideEntry, PeptideLog, IntensityStats, node/edge props)

### Key Patterns
- Peptides and intensities are serialized as delimited strings over the API, parsed into structured `PeptideLog` objects on the frontend
- Isoform colors are assigned cyclically from `theme.ts` constants and tracked in `isoformColorMapping`
- Layout is computed lazily via `calculatePositionData()` (BFS traversal) then applied by the active layout mode
- Components use `React.memo` + Zustand shallow selectors to minimize re-renders on large graphs

### Data Directories
- `data/` — production .graphml files
- `test_data/` — test fixtures (38 expected GraphML files)
- `generated/` — output nodes.json + edges.json consumed by frontend
